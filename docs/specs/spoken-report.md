# 語音報告

## Problem Statement

使用者用說的操作，卻要看畫面才知道結果。構想的情境（智慧眼鏡、穿戴裝置）不一定有畫面可看，結果也要能用聽的取得。

## Solution

每個使用者意圖輪到時（見 [queue](queue.md)），把成功的結果用 TTS 念出來：改變資料的動作只念摘要，查詢依黑板上實際顯示的項目逐項念。念的內容由規則從執行器的結構化結果組成，不經過 AI。

一句話：**操作完成，用最少的語音告知結果；查詢才逐項念，預設 3 項。**

## User Stories

1. 作為使用者，我想新增、修改、刪除、設定完成後聽到簡短的結果，不用看畫面。
2. 作為使用者，我想查詢時聽到黑板上的項目，預設只念前 3 項，被問到時可以選擇全部念完。
3. 作為使用者，我想說過「全部念完」之後，之後的查詢都直接念全部，直到我打斷為止。
4. 作為使用者，我想說「停止」就能停下；念的時候說別的事不會打斷，那件事排在後面。
5. 作為使用者，我想小精靈問我問題時也念出來，不用看畫面就知道它在等我回答。
6. 作為使用者，我想用按鈕或說的關掉語音報告，例如在需要安靜的地方。
7. 作為開發者，我想在測試紀錄看到念了什麼、什麼時候被打斷。

## Implementation Decisions

### 什麼時候念

- 每個使用者意圖輪到時念一次：它的指令全部結束，或停在釐清、刪除確認時，念已經成功的結果，依指令的順序。刪除確認回答 yes 後，念刪除的結果。
- 念完才換到下一個結果：念的時間就是這個結果的報告顯示時間（見 [queue](queue.md)）。
- 聊天的回應照原文念（見 [chat](chat.md)）。
- 提示對話框念目前這一頁的內容（連結念頁名）；換頁時（說的或點的）中斷正在念的提示，改念新的一頁（見 [help](help.md)）。
- 念問題：釐清、刪除確認、錯誤確認的問題照回話的文字念，接在成功的結果後面。問題會擋住後面的結果，使用者沒看畫面也要知道小精靈在等回答；問題開始念的時候就是「問題出現」，之後開口的第一句話是回答（見 [queue](queue.md) 的「等回答與插隊」）。
  - 問題裡列出的項目（釐清、刪除確認）和查詢一樣只念前 3 項，超過時接著念「還有 N 項請看畫面。」再念問句；回話照樣列出全部。
  - 刪除確認與「要全部念完嗎」的說法不含回答的關鍵字：念的期間聽到的話是正在念的文字的一部分時會被當成回音丟掉（見 [queue](queue.md) 的「一句話進來時」），說法裡有「確定」，回答「確定」就要等念完才算。錯誤確認例外：它要教使用者說「重試」「略過」，念的期間可以按彈窗的按鈕。
- 不念：放棄、找不到、聽不懂。沒有成功的結果、聊天的回應，也沒有問題就不念。
- 黑板的上一頁、下一頁、顯示全部、設定顯示（checkbox）不念，不論用說的或點的；上一頁、下一頁改成翻提示時，照提示對話框念。
- 語音報告開關關閉時都不念（見「語音報告開關」）。

### 念的內容

同一種動作的結果合併；查詢的內容固定念在最後。

| 動作 | 念的內容 |
|---|---|
| 新增 | 「已新增一個待辦事項。」多筆：「已新增 N 個待辦事項。」 |
| 修改 | 只念改到的部分。日期或時刻有改：「已將待辦事項時間修改為 1 月 1 日下午 1 點。」（一律念完整的日期＋時刻）；內容有改：「已將待辦事項內容修改為〇〇。」兩者都改：「已將待辦事項時間修改為…，內容修改為〇〇。」 |
| 刪除 | 「已刪除 N 個待辦事項。」 |
| 設定完成 | 「已將〇〇設為完成。」或「已將〇〇設為未完成。」 |
| 查詢日期 | 「下週五是 10 月 9 日星期五。」 |
| 查詢待辦 | 「有 N 個待辦事項：<項目>；<項目>；<項目>。」沒有結果：「沒有待辦事項。」 |
| 查天氣 | 每一天一句（句子見 [weather](weather.md) 的「回報」）。`readAll` 打開時念全部；關閉時念前 3 天，超過時最後加「其他天請看畫面。」，不進入「要全部念完嗎」的等待。失敗時念原因 |

**查詢的項目**：查詢執行完後黑板上看得到的項目，順序和黑板相同，不念黑板以外的東西。每一項念日期、星期、時刻、內容，例如「10 月 9 日星期五早上 9 點，部門會議」；沒有時間的不念時刻，例如「10 月 5 日星期一，看牙醫」；沒有日期的只念內容，例如「看牙醫」；已完成的項目後面加「已完成」。

**念法**（和畫面的格式不同）：

- 日期：「10 月 9 日星期五」。
- 時刻依時段：0～5 點凌晨、6～8 點清晨、9～11 點早上、12 點中午、13～17 點下午、18～23 點晚上；整點念「下午 1 點」，否則念「下午 1 點 30 分」。

### 只念 3 項與 `readAll`

- `readAll` 預設關閉，只在記憶體裡；App 啟動與重新開始時是關閉。
- 查詢的項目超過 3 項時：
  - `readAll` 打開：念全部。
  - `readAll` 關閉：念前 3 項，接著念並在回話顯示「還有其他項目，其他的也念出來嗎？」，進入等待，後面的結果不出現。回答（問題開始念之後開口的第一句話，插隊）用關鍵字判斷，不送 AI：
    - **要**（例如「好」「要」「念完」「全部」「繼續」）：打開 `readAll`，念剩下的項目，念完才換到下一個結果。
    - **不要**（例如「不要」「不用」「算了」）：結束等待，`readAll` 維持關閉，換到下一個結果。
    - **其他**：`readAll` 重設，結束等待；這句話照常判斷，馬上呈現（仍屬於目前的生命週期）。
- **全部念完**是執行器（見 [todos](todos.md)）：打開 `readAll`，念「好，之後會全部念完。」。
  - 整句話只有「全部念出來」「全部念完」，且沒在等「要全部念完嗎」：由規則判斷產生，不送 AI（見 [judge-tool](judge-tool.md)）。
  - 句子裡還有其他內容（「下週有什麼事，全部念出來」）：先打開 `readAll`，整句照常交給 AI 判斷。
- 念完沒有被中斷時，`readAll` 維持原狀。

### 中斷

- **正在念**的時候，只有下面四種情況會停止，`readAll` 重設成關閉：
  - 說「停止」（輔助關鍵字，去掉標點與空白後完全相同；不排進佇列、不送 AI）：目前的結果結束，換到下一個。在等「要全部念完嗎」時和「不要」相同；在念釐清、刪除確認、錯誤確認的問題時只停止念，問題仍然在等回答；沒在念就不做任何事。
  - 按復原、重做（見 [queue](queue.md) 的「觸控」）。
  - 關閉語音報告開關。
  - 說「全部取消」（見 [queue](queue.md)）。
- 念提示頁是例外：換頁（點的、說的）或下一個結果輪到時，停止念這一頁，改念新的一頁或新的結果；不重設 `readAll`（見 [help](help.md)；念提示不佔報告顯示時間，見 [queue](queue.md)）。
- 其他的話、測試輸入、點方框、checkbox、上一頁與下一頁都**不會**中斷：說的話排進輸入佇列，結果排在後面。
- 「停止」要等定稿才比對得到，從開口到停下大約是停頓 1.5 秒加上定稿的時間。
- 念的期間開口、內容是正在念的文字的一部分的話，是小精靈自己的聲音漏進麥克風，丟掉（見 [queue](queue.md) 的「一句話進來時」）。
- 中斷後還沒念的部分丟掉，不會接著念。

### 語音報告開關

- 使用者畫面右上角、齒輪的左邊：打開是 `speaker.wave.2.fill`，關閉是 `speaker.slash`；點擊範圍至少 44pt。
- 預設打開；狀態存檔（UserDefaults，和黑板的 checkbox 相同）。
- 關閉時：正在念就停止（算中斷），在等「要全部念完嗎」就結束等待；目前的結果改用語音報告關閉的報告顯示時間，從關閉的那一刻計算（見 [queue](queue.md)）。之後都不念，也不問「要全部念完嗎？」；回話照常顯示。
- 語音切換：一句話去掉標點與空白後完全等於「關閉語音報告」「關閉音效」「打開語音報告」「打開音效」時切換，不排進佇列、不送 AI，任何狀態都適用。

### TTS 與麥克風

- TTS 用系統的 `AVSpeechSynthesizer`、zh-TW 語音：iOS 與 macOS 都有，在裝置上執行，不需要網路，沒有次數與額度限制，連續的句子依序念。使用者在系統設定下載的增強語音品質較好，沒有就用內建的語音。
- 念的時候繼續聆聽，打開系統的回音消除（`AVAudioEngine` 輸入的 voice processing），從麥克風的聲音扣掉小精靈自己的聲音，所以使用者可以邊聽邊說下一件事。iOS 的 audio session 改成同時播放與錄音，從喇叭播放。
- 回音消除不完美時，小精靈的聲音可能被辨識成一句話。是正在念的文字的一部分就丟掉；有錯字時擋不住，會變成新的使用者意圖，所以列為手動驗證的第一項。

### 紀錄

- 測試紀錄記一行「報告」：念的全文；被中斷時記一行「中斷」：原因（停止、復原、重做、關閉開關、全部取消）。
- 單元測試時不念。

### 結構

- 執行器完成一條指令時只回傳結構化的結果（新增的待辦、修改前後、刪除的數量、設定完成、日期的範圍、查詢的項目、天氣的句子；設定顯示、復原與重做、換頁只有回話，不念），不組文字。
- 回話的文字與念的句子都由規則從同一個結構化結果組成，小精靈的措辭只在這一處；念的句子另外用到 `readAll`，並回傳還沒念的項目。日期與時刻的念法（「10月9日星期五」「下午1點30分」）是日期說法的一部分，天氣的句子也用。
- TTS 是可替換的介面（念完或被停止才返回、停止），單元測試用假的實作。
- 念的狀態（開關、`readAll`、正在念、念提示、念的期間）與中斷的規則由語音報告 module 管理；念什麼、什麼時候念由小精靈決定。

## Testing Decisions

- 單元測試（macOS）：
  - 念的內容：表格的每一列、多筆合併、查詢念 3 項並詢問、查天氣念 3 天加「其他天請看畫面。」而不詢問、問題裡的項目念 3 項加「還有 N 項請看畫面。」、刪除確認與要全部念完嗎的說法不含回答的關鍵字、`readAll` 念全部、沒有結果、日期與時刻的念法、只有失敗時不念
  - 關鍵字：要（含「繼續」）／不要／其他、全部念完、停止、開關語音報告
  - 流程（假的 TTS）：輪到才念，念完才換下一個；停在刪除確認時念已成功的結果與問題，回答 yes 後念刪除；詢問後回答要、繼續、不要、其他；念的時候說停止、按復原或重做、關閉開關、全部取消就停止並重設 `readAll`；念的時候說別的話、送出測試輸入、點方框不停止；念問題時說停止，問題仍在等回答；整句只有「全部念完」不送 AI；開關關閉時不念也不詢問；開關存檔
- 手動驗證（實機）：
  - [ ] 回音消除：用喇叭播放時，自己的聲音不會變成新的使用者意圖（iPhone、Mac）
  - [ ] 說「停止」到停下的延遲可以接受
  - [ ] iPhone 從喇叭播放，不是聽筒；戴耳機時正常
  - [ ] 打開回音消除後語音辨識照常（macOS 的麥克風格式可能改變）
  - [ ] 念的句子自然、長度適當

## Out of Scope

- 黑板翻頁、設定顯示時念
- 中斷後接著念剩下的
- 調整語速、選擇語音
- 由 AI 產生任務結果的念法（聊天的回應本身是 AI 寫的，照原文念）
