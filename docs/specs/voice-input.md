# 語音輸入階段

## Problem Statement

使用者只用說話和小精靈溝通。語音輸入要提供穩定、不會再變動的文字，並判斷一句話何時說完，交給校正階段。不需要精準：錯字由校正階段修正。

## Solution

App 開啟就持續聆聽 zh-TW；除錯 UI 的語音輸入開關關閉時停止聆聽（見 [ui](ui.md)）。只累積辨識器的確定結果；停頓 1.5 秒後把剩下的話定稿，串成一句話放進輸入佇列。

一句話：**確定結果累積起來，停頓 1.5 秒就定稿成一句話排隊。**

## User Stories

1. 作為使用者，我想 App 一開啟就開始聆聽，不用按任何東西。
2. 作為使用者，我想說完停一下，小精靈就開始處理，不用說喚醒詞或結尾詞。
3. 作為使用者，我想辨識器把一句話切成好幾段時，小精靈仍當成同一句話處理。
4. 作為使用者，我想小精靈處理中或念結果時說的話不會被丟掉，而是依序排隊。
5. 作為使用者，我想第一次使用時被詢問麥克風權限，並自動下載缺少的語音資源。
6. 作為開發者，我想在除錯 UI 看到即時的暫定結果與累積中的確定結果。

## Implementation Decisions

- **語音辨識（SpeechManager）**：沿用上個專案的模組。`SpeechAnalyzer`＋`SpeechTranscriber`，語言 zh-TW；麥克風格式以音訊轉換器轉成辨識器格式，保留原始時間戳；提供 `finalize(through:)`。
- **回音消除**：麥克風輸入打開 voice processing，語音報告念的時候繼續聆聽而不會聽到小精靈自己（見 [spoken-report](spoken-report.md)）。iOS 的 audio session 是同時播放與錄音，從喇叭播放。
- **權限**：App Sandbox 開啟音訊輸入；Info.plist 提供麥克風與語音辨識的用途說明。
- **規則**
  1. 確定結果：接在累積中的文字後面。
  2. 暫定結果：只顯示在除錯 UI，不參與處理。
  3. 暫定結果或確定結果有變化，就重新計時。
  4. 1.5 秒沒有變化且有內容（累積的確定結果或暫定結果）：呼叫 `finalize(through:)` 定稿到目前為止，等定稿的確定結果到達後，把累積的文字當成一句話交出，清空累積。
  5. **開口時間**：這句話第一個辨識結果（暫定或確定）出現的時間，和一句話一起交出。用來判斷這句話是不是回答、是不是在念的期間開口的（見 [queue](queue.md) 的「等回答與插隊」「一句話進來時」）。
- **一句話交出之後**：依序檢查全部取消、輔助關鍵字、回音、回答，其他的放進輸入佇列（見 [queue](queue.md)）。測試輸入的每一行也各自是一句話，開口時間是送出的時間，走同一個流程。
- 停頓時間 1.5 秒為暫定值，實測後調整。

## Testing Decisions

- 停頓判斷與累積邏輯與 Speech 框架分開，以單元測試驗證：給確定結果、暫定結果與時間，檢查送出的一句話。
  - 多段確定結果串成一句話
  - 1.5 秒內有新結果就不送出
  - 沒有內容時不送出
  - 開口時間是第一個辨識結果的時間，不是定稿的時間
- 手動驗證：
  - [ ] 連續聆聽超過 10 分鐘不中斷
  - [ ] 停頓後多久送出；定稿花多久
  - [ ] 話說一半停頓被提早送出的頻率

## Out of Scope

- 暫定結果參與判斷
- 喚醒詞
- 語言切換（只支援 zh-TW）
- 小精靈說話時暫停聆聽（改用回音消除，見 [spoken-report](spoken-report.md)）
