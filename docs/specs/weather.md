# 天氣

## Problem Statement

使用者常在安排待辦時順口問天氣（「明天會下雨嗎」「下週五台北天氣如何」），App 沒有這個能力，只能由聊天說「不提供天氣資訊」。構想是「說出需求，AI 推斷意圖並執行」，App 以外的能力也應該能用同一種方式接上。

## Solution

天氣是第一個**額外能力**（見憲章 P1-4、[CONTEXT](../../CONTEXT.md)）：待辦清單以外的能力，只透過小精靈使用，沒有自己的 UI，不改變待辦。

AI 判斷（或規則判斷）輸出指令「查天氣」，欄位是日期與地點；輪到時小精靈向天氣服務查預報，用規則組成句子，念出來並顯示在回話。日期與時間的說法沿用 [date-time](date-time.md) 的換算，和查詢待辦相同；沒說地點就查所在地，用 App 內建的台灣鄉鎮市區邊界說出所在地是哪裡。

一句話：**查天氣是一條不改待辦的指令：日期照查詢的換算，地點沒說就是所在地（說出鄉鎮市區），結果由規則組成句子回報。**

## User Stories

1. 作為使用者，我想問「明天會下雨嗎」「今天天氣如何」時，小精靈念出所在地那天的天氣、溫度與降雨機率，並說出所在地是哪個鄉鎮市區（例如「臺北市大安區」）。
2. 作為使用者，我想問「下週五台北天氣如何」時，小精靈查台北，回報時用我說的地名。
3. 作為使用者，我想問「明天下午會下雨嗎」「今天中午以前」時，只聽那段時間的天氣。
4. 作為使用者，我想問「下週天氣」時，聽到每一天的天氣，不要念太久。
5. 作為使用者，我想查不到時（沒有定位權限、找不到地名、太遠的日期、沒有網路），小精靈告訴我原因。
6. 作為使用者，我想說「提醒我明天看天氣預報」時，是新增待辦，不是查天氣。
7. 作為開發者，我想在測試紀錄看到查詢的地點、範圍與結果，或失敗的原因。

## Implementation Decisions

### 指令

| 指令 | 欄位 | 行為 | 放棄條件 |
|---|---|---|---|
| 查天氣 | 日期?、地點? | 查那段日期（與時間）、那個地點的預報，回報每一天一句 | 無法換算、「下次」「所有」 |

- 不改待辦、不移動黑板、不記 undo 狀態、不寫存檔。
- 不看黑板：黑板是待辦的指令的前置條件（見 [todos](todos.md)），天氣不是待辦。沒說日期就是今天。
- 沒有提醒事項的權限時照常可以查（天氣不用存檔）。
- 放棄時回報原因，例如「天氣要說哪一天」；沒有資料要還原。

### 判斷

- AI 判斷：判斷提示詞與輸出結構多一種指令「查天氣」，欄位 `date`（日期字串，同其他指令）、`place`（使用者說的地名，照原文，沒說就省略）。規則從「跟待辦與日期無關…只輸出聽不懂」改成「跟待辦、日期與天氣無關」。問的是天氣（「會下雨嗎」「要帶傘嗎」「幾度」）就是查天氣；要記下一件跟天氣有關的事（「提醒我明天看天氣預報」「明天天氣好的話去爬山」）是新增待辦。
- 規則判斷：「今天會下雨嗎」「明天會下雨嗎」兩句固定的話（見 [judge-tool](judge-tool.md)）。

### 日期與時間

- 日期照 [date-time](date-time.md) 換算成一段日期（範圍是最小單位的整段：「明天」一天、「下週」整週）。
- 時間照「範圍」那一欄換算（和查詢待辦相同）：「早上」09:00～12:00、「中午以前」未滿 12:00、「晚上」18:00 到當天結束、「下午3點」那一個小時、「下午1點到3點」兩端都含。時間要接在一天之後（「下週晚上」不合法而放棄，見 [date-time](date-time.md) 的「不合法的組合」）。
- 天氣服務只有今天起 16 天的預報：
  - 整段都在範圍外（今天以前、16 天以後）：回報「只能查今天起 16 天內的天氣」。
  - 一部分在範圍外：回報查得到的天，最後加「其他天只能查今天起 16 天內的天氣」。
- 今天已經過去的時間只算還沒到的小時；整段都過了，回報「那段時間已經過了」。

### 地點

- 沒說地點：所在地（定位）。第一次查所在地時才請求定位權限，App 啟動時不請求。
- 沒說地點時的名稱：用 App 內建的鄉鎮市區邊界，判斷定位的座標（原始精度，判斷在裝置上做、不送出）落在哪一區，名稱是「縣市＋鄉鎮市區」（例如「臺北市大安區」）。不在台灣、或判斷不出來時，名稱是「所在地」。
  - 不用系統的反向地名搜尋（MapKit）：Apple 的條款不允許不顯示 Apple 地圖就顯示它的地圖資料（Apple Developer Program License Agreement 的 Attachment 6 §2.4），而額外能力沒有自己的 UI（憲章 P1-4）。
- 說了地點：用系統的地名搜尋轉成座標，取第一筆，不釐清。回報的地點名稱用使用者說的地名（`place`），不顯示搜尋結果的名稱，理由同上。
- 地名由 AI 判斷填寫，送到地名搜尋前由 App 檢查，不像地名就不送出，回報「這不像地名，沒有查詢」（不重複那段文字）：超過 20 字、有連續 4 個以上的數字、或有同時含英文字母與數字的英數字串（例如金鑰、密碼）。理由見憲章 D1 的「外部功能的資料進出」。
- 座標送給天氣服務前四捨五入到小數 2 位（約 1 公里）：預報的網格本來就是公里級，不需要更精確的位置。測試紀錄記的也是這個座標。

### 資料

- 天氣服務是外部依賴，目前是 Open-Meteo（不用註冊與 key；資料 CC BY 4.0）。免費版只限非商業用途（[terms](https://open-meteo.com/en/terms)）：有廣告、訂閱，或整合進商業產品、宣傳就要改付費方案；免費且沒有營利的 App 上架不算商用，邊界情況先問 Open-Meteo。介面只有「位置＋日期範圍 → 每日預報」與「位置＋時間範圍 → 逐小時預報」，換服務只換實作。
- 送出與收回（憲章 D1 的「外部功能的資料進出」）：
  - 送出：座標（小數 2 位）、日期範圍與要的欄位；不送使用者的話。Open-Meteo 免費版可能為了伺服器維護與防止濫用記錄 IP 等資訊，紀錄 90 天後刪除（[terms](https://open-meteo.com/en/terms)）。
  - 地名搜尋（MapKit）：送出使用者說的地名（經過上面的檢查）；收回的只用座標，不顯示、不進到 AI。
  - 鄉鎮市區邊界是 App 內建的資料，不送出任何東西。
  - 收回：只取數字與天氣代碼，句子由規則組成；服務的錯誤原因只寫進測試紀錄，回話顯示固定的「天氣服務沒有回應」，所以外部的文字不會經由畫面資訊進到 AI。
- 沒說時間：用每日預報的天氣代碼、最高與最低溫、最高降雨機率。
- 說了時間：用那段時間每個小時的預報，濃縮成一句：天氣代碼取最大的（WMO 代碼大致依嚴重程度排列，有一小時下雨就是雨）、溫度取最低～最高、降雨機率取最高的一小時。
- 天氣代碼（WMO）轉成中文：

| 代碼 | 中文 |
|---|---|
| 0 | 晴 |
| 1 | 大致晴朗 |
| 2 | 多雲 |
| 3 | 陰 |
| 45、48 | 霧 |
| 51～57 | 毛毛雨 |
| 61～65 | 雨 |
| 66、67 | 凍雨 |
| 71～77 | 雪 |
| 80～82 | 陣雨 |
| 85、86 | 陣雪 |
| 95～99 | 雷雨 |

### 回報

- 每一天一句，由規則組成：`<地點>，<日期><時間>：<天氣>，<低>～<高> 度，降雨機率 <N>%。` 地點見上面的「地點」；日期的念法和語音報告相同（「10月7日星期三」）；時間是使用者說的那段（「下午」「中午以前」），沒說就省略。溫度四捨五入到整數，低和高相同時只說一個數字。
  - 例：「臺北市大安區，10月7日星期三：晴，18～25 度，降雨機率 20%。」
  - 例：「台北，10月9日星期五下午：陣雨，22～26 度，降雨機率 60%。」
- 回話顯示全部的句子；語音報告念幾天見 [spoken-report](spoken-report.md) 的「念的內容」。
- 查詢中回話顯示「查天氣中…」；查天氣在輪到時才查，查完才算這個結果呈現完。
- 失敗不進入錯誤確認，回話與語音報告說原因：
  - 沒有定位權限：「沒有定位權限，查不到所在地的天氣，請到系統設定允許」
  - 有權限但拿不到位置：「找不到所在地」
  - 找不到地名：「找不到「X」這個地方」
  - 天氣服務失敗或沒有網路：「天氣服務沒有回應」
- 小精靈的狀態與插畫和其他完成的結果相同。

### 標示

Open-Meteo 的資料授權是 CC BY 4.0（[licence](https://open-meteo.com/en/licence)）：顯示資料的地方旁邊要有連到 Open-Meteo 的連結、連到授權的連結，並註明有改動（濃縮逐小時預報、代碼翻成中文）。標示文字：「天氣資料：Open-Meteo.com（CC BY 4.0），經過整理」，Open-Meteo.com 與 CC BY 4.0 各自可以點開。

鄉鎮市區邊界是內政部國土測繪中心的「鄉鎮市區界線(TWD97經緯度)」（[data.gov.tw](https://data.gov.tw/dataset/7441)），授權是政府資料開放授權條款第 1 版（[license](https://data.gov.tw/license)）：要標示提供機關、年份、資料名稱，說明依這個條款釋出，並附條款的連結。條款沒有規定標示的位置。標示文字：「地名資料：內政部國土測繪中心 2025 鄉鎮市區界線（1140318 版），依政府資料開放授權條款釋出，經過簡化」，政府資料開放授權條款可以點開。

- 天氣資料的標示是查到天氣的那則回話的一部分：在內容下面用小字顯示，一直跟著那則回話（見 [ui](ui.md) 的「對話流」）。查不到時沒有資料，沒有標示。其他回話都沒有標示。
- 地名資料的標示只放在設定頁。
- 設定頁最下面有這兩行（見 [settings](settings.md) 的「天氣資料的標示」）。
- 語音報告不念標示。

標示是額外能力唯一出現在畫面上的東西，理由是授權規定（憲章 P1-1 的現實限制），不是額外能力自己的 UI（P1-4）。

### 紀錄

測試紀錄的執行多一行「天氣」：`<地點>（座標）<開始>~<結束>` 與每天的結果，或失敗的原因。
- 每次呼叫天氣服務另外記兩行「天氣服務」：`請求：<完整網址>`、`回應：HTTP <狀態> <原始 JSON>`；連不上時回應記錯誤。用來在實機上用「分享測試紀錄」確認送出了什麼、收到了什麼（憲章 D1 的「外部功能的資料進出」）。

### 結構

- Domain：天氣代碼表、把日期與時間換算成查詢範圍（含 16 天的限制與過去的時間）、濃縮逐小時預報、組句子、座標落在哪個鄉鎮市區；都是純函式。
- Application：天氣服務的介面（讓測試可以換掉網路與定位）；小精靈執行查天氣（非同步，所以和復原、上一頁一樣不在 `CommandExecutor` 裡）。
- Infrastructure/Weather：Open-Meteo、地名搜尋（MapKit `MKGeocodingRequest`）、所在地（CoreLocation）、鄉鎮市區邊界的資料（`towns.json`，由 `tools/make_towns.py` 從內政部的資料產生：邊界簡化到約 100 公尺，隨機抽樣的判斷結果和原始邊界 99.6% 相同；資料更新時重跑）。macOS 打開 sandbox 的定位 entitlement；iOS 與 macOS 的 Info.plist 寫定位用途的說明。

## Testing Decisions

- 單元測試（macOS，假的天氣服務、地名搜尋與定位）：
  - 範圍：「明天」「下週」「明天下午」「今天中午以前」「下午3點」「下午1點到3點」換成的日期與時間；整段超過 16 天、部分超過、今天以前；今天已經過去的時間只算剩下的，整段都過了；「下次」「所有」「下週晚上」放棄。
  - 濃縮：天氣代碼取最大、溫度取最低～最高、降雨機率取最高。
  - 代碼表：每一列。
  - 句子：每日、有時間、溫度四捨五入、低高相同只說一個數字。
  - 地點名稱：沒說地點時用鄉鎮市區的名稱，不在任何一區是「所在地」；說了地點用使用者說的地名，不用搜尋結果的名稱。
  - 鄉鎮市區：座標在邊界內、在外框內但在邊界外、多個區塊（離島）；App 內建的資料能讀出 368 個鄉鎮市區，台北 101 是「臺北市信義區」。
  - 標示：查到天氣的那則回話有天氣資料的標示，下一句話輪到後仍然有；查不到、其他回話沒有；標示文字的連結與「經過整理」、地名資料的版本與「經過簡化」。
  - 紀錄：天氣服務的請求與回應寫進測試紀錄（「天氣服務」）。
  - 送出：地名檢查（超過 20 字、連續 4 個數字、英數混合的字串不送，「台北101」照送）；座標四捨五入到小數 2 位才送給天氣服務。
  - 流程：有 `place` 時用地名搜尋，沒有時用所在地；沒有定位權限、找不到地名、服務失敗的回報，不進入錯誤確認；不改待辦、不移動黑板、不記 undo；沒有提醒事項的權限時照常查。
  - JSON：解析出 `place`；規則判斷：「今天會下雨嗎」「明天會下雨嗎」命中、日期正確；「明天會下雨嗎？」去掉標點也命中；「明天下午會下雨嗎」不命中，交給 AI。
- 手動驗證（實機）：
  - [ ] 「今天會下雨嗎」「明天會下雨嗎」：測試紀錄是「規則：查天氣（…）」，第一次跳出定位權限，允許後念出所在地的鄉鎮市區（例如「臺北市大安區」）與天氣
  - [ ] 天氣的回話下面有 Open-Meteo 的標示，連結能點開；下一句話輪到後，標示仍然跟著那則回話
  - [ ] 「下週五台北天氣如何」：念出「台北」那天的天氣
  - [ ] 「明天下午會下雨嗎」：只說下午那段
  - [ ] 「下週天氣」：回話列出 7 天，語音念 3 天加「其他天請看畫面」
  - [ ] 拒絕定位權限、關掉網路、「火星天氣」：各自回報原因
  - [ ] 「提醒我明天看天氣預報」「明天天氣好的話去爬山」是新增待辦（judge-cases）

## Out of Scope

- 現在的天氣、逐分鐘、天氣警報、空氣品質、日出日落
- 歷史天氣
- 用天氣改變待辦（例如下雨就延後）、在黑板上顯示天氣
- 同名地點的釐清
- 天氣的規則判斷句型（只收兩句固定的話）
