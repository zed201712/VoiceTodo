# 佇列與報告顯示時間

## Problem Statement

判斷一句話要 2～18 秒。之前一次只處理一句話：使用者連說幾句，每句都要等前一句處理完才開始判斷；語音報告念的時候開口就會中斷，使用者想接著說下一件事，就聽不完上一個結果。

## Solution

把「解讀一句話」和「執行、呈現結果」分開。背景平行地把每句話解讀成使用者意圖，這一步不改任何狀態；使用者意圖照說話的順序，一個一個執行、顯示、報告，每個結果佔一段報告顯示時間。使用者聽前一個結果的時間，正好拿來準備下一個。

一句話：**背景平行地把一句話解讀成使用者意圖；使用者意圖照說話的順序，一個一個執行、呈現。**

## User Stories

1. 作為使用者，我想連續說幾件事，每個結果念完後下一個結果馬上出現，不用每句都等 AI。
2. 作為使用者，我想結果照我說的順序出現，即使後說的比較早處理完。
3. 作為使用者，我想小精靈念結果時我可以接著說下一件事，不會打斷它。
4. 作為使用者，我想小精靈在問我問題時，後面準備好的結果不會跳出來把問題蓋掉。
5. 作為使用者，我想回答小精靈的問題時，我的回答馬上被處理，不用排在之前說的話後面。
6. 作為使用者，我想說「全部取消」就丟掉所有還沒輪到的事。
7. 作為使用者，我想關掉語音報告時，每個結果也停留一段夠我看完的時間。
8. 作為開發者，我想在除錯 UI 與測試紀錄看到每句話在佇列裡的狀態。

## Implementation Decisions

### 三個佇列與生命週期

| 佇列 | 內容 | 順序 |
|---|---|---|
| 輸入佇列 | 定稿的一句話 | 說話的順序；每一筆開始一個生命週期 |
| 執行佇列 | 正在解讀的一句話 | 照輸入佇列的順序開始，同時最多 2 句，完成的順序不一定 |
| 結果佇列 | 解讀好的使用者意圖 | 和輸入佇列一一對應、順序相同 |

- **生命週期**：從一句話進入輸入佇列開始，到它的使用者意圖執行完、呈現完（包括所有釐清、確認）為止。
- **使用者意圖**：一句話解讀之後的結果。規則判斷命中時，比對到的當下就產生；其他的話在平行處理階段（校正 ∥ 判斷）結束時產生。內容是下列其中一種：
  - 指令清單
  - 聊天的回應（判斷沒有指令時，見 [chat](chat.md)）
  - 判斷失敗（輪到它時進入錯誤確認，見 [recovery](recovery.md)）
- 釐清、確認的需求是執行器執行時才發現的（例如在黑板上找到多筆），所以使用者意圖本身是完整的，輪到它執行時才變成「待釐清的使用者意圖」。

### 背景只解讀，不改狀態

**前提：執行佇列不能影響目前的任務。** 輪到之前，背景的工作沒有任何看得到的效果：不改資料、不移動黑板、不記 undo、不顯示、不念、不跳彈窗。

- 定稿當下做：規則校正（拿掉多餘的空白）、拍畫面資訊的快照。
- 背景做：關鍵字比對、規則判斷、校正 ∥ 判斷、聊天。這些步驟都只讀句子與快照。
- 輪到時才做：執行器（換算日期、在黑板上找目標、改資料、移動黑板）、記 undo、顯示、報告、錯誤確認。執行器用的是前一個結果執行完之後的黑板。
- 畫面資訊的快照在**定稿時**拍：使用者說這句話時看到的畫面（見 [screen-info](screen-info.md)）。
- 聊天的回應在背景先準備；輪到時，如果黑板或待辦和拍快照時不同（前面的結果改了東西），就用現在的畫面重做一次聊天。只比對黑板與待辦，不比對現在時間與回話。
- 同時最多 2 句：一句產生使用者意圖、放進結果佇列後，下一句才開始。結果佇列裡等著的、正在呈現的都不佔名額；校正後的重判算在同一句裡；回答與輪到時重做的聊天不受上限限制。2 是暫定值，實測後調整。
- 手動 AI：開發者一次只能貼一份 AI 回應，所以一次只解讀一句，照輸入順序顯示使用者提示詞。
- 在設定裡換自動 AI：已經送出的使用者提示詞用原本的 AI 做完，之後的用新的 AI。

### 呈現

一次只呈現一個結果（目前的結果）。輪到一個使用者意圖時，執行它、顯示、報告；報告顯示時間結束、而且沒在等回答，才輪到下一個。

- 輪到的使用者意圖還沒解讀好時，回話顯示「思考中…」，好了就執行。
- 後面沒有使用者意圖時，目前的結果一直留在畫面上。
- 判斷失敗的結果只有輪到它時才進入錯誤確認；後面的使用者意圖照樣在背景準備，但不顯示。

### 報告顯示時間

一個結果最少佔用的時間；時間到了只代表可以換到下一個。

- 語音報告打開、而且這個結果有要念的內容：念完就結束。
- 語音報告關閉，或這個結果沒有要念的內容（例如放棄、找不到、翻頁、設定顯示）：**2 秒 + 字數 × 0.1 秒，最多 5 秒**。字數是回話裡這個結果的文字，不算空白。
- 等回答的時候不計時；回答處理完後，用回答的結果重新計算。
- 結果只有說明、上個提示、下個提示（見 [help](help.md)）：顯示出來就結束，念提示不佔報告顯示時間；下一個結果輪到時中斷念提示（見 [spoken-report](spoken-report.md)）。
- 2 秒、0.1 秒、5 秒是暫定值，實測後調整。

### 等回答與插隊

目前的結果有四種會等回答：釐清、刪除確認、要全部念完嗎（見 [spoken-report](spoken-report.md)）、錯誤確認（見 [recovery](recovery.md)）。等回答時，後面的結果都不出現。

- **問題出現**：語音報告打開時，問題開始念的時候；關閉時，問題顯示在回話的時候。
- **回答**：問題出現之後才**開口**的第一句話（不含優先關鍵字與輔助關鍵字，見「一句話進來時」）。開口的時間是這句話第一個辨識結果的時間；測試輸入的一行以送出的時間算。問題出現之前開口的話，即使在問題出現後才定稿，也是新的使用者意圖。
- 回答**插隊**：不進入任何佇列，馬上處理，屬於目前的生命週期，不開始新的生命週期。
- 回答不論內容都插隊。內容是新的需求時，取代原本的任務，馬上呈現：

| 在等什麼 | 回答 | 結果 |
|---|---|---|
| 刪除確認 | yes／no | 刪除，或取消 |
| 刪除確認 | other | 改做釐清後判斷，新的指令取代原本的刪除 |
| 釐清 | 新的指令 | 原本的任務取消，執行新的指令 |
| 釐清 | 聽不懂、空清單 | 原本的任務取消，換到下一個結果 |
| 要全部念完嗎 | 要／不要 | 念完剩下的，或換到下一個結果 |
| 要全部念完嗎 | 其他 | `readAll` 重設，這句話照常判斷，馬上呈現 |
| 錯誤確認 | 重試、略過、復原、重做 | 見 [recovery](recovery.md) |
| 錯誤確認 | 其他 | 等於略過，這句話照常判斷，馬上呈現 |

- 想直接看後面的結果，要用否定的回答（「取消」「不要」）結束目前的結果。
- 沒有回答就一直等。

### 一句話進來時

語音定稿或測試輸入的一行，依序檢查：

1. **優先關鍵字「全部取消」**（見「全部取消」）。
2. **輔助關鍵字**：停止、打開／關閉語音報告、關閉語音（見 [flow](flow.md)）。只控制報告與麥克風，不碰任務與佇列，馬上處理。
3. **回音**：語音報告正在念、而且這句話是在念的期間開口的：去掉標點與空白後，是正在念的文字的一部分，就丟掉。這是小精靈自己的聲音漏進麥克風，不排進佇列，只記紀錄。例外：正在念提示頁時，命中規則判斷的提示句型（見 [judge-tool](judge-tool.md) 的「提示」）的話不是回音：提示頁裡本來就有連結名稱與要使用者照著說的話，回音漏進來通常是一長串，不會剛好是這幾個字。
4. **回答**：目前的結果在等回答，而且這句話是回答（見「等回答與插隊」）：插隊處理。
5. 其他：放進輸入佇列。

### 全部取消

- 關鍵字：去掉標點與空白後完全等於「全部取消」「全部停止」「取消全部」「停止全部」。
- **只比對定稿的原句**（測試輸入的一行也算）：比對在定稿當下，比校正早，AI 校正改出來的句子不算；AI 判斷也沒有對應的指令。一定要語音直接辨識成功。理由：校正在執行佇列裡，結果回來時後面的話可能已經排進來，會取消在它之後才說的話；而且只要求字數不變的校正，可能把四個字的句子改成「全部取消」。
- 結果：
  - 輸入佇列、執行佇列、結果佇列全部清空；背景正在進行的 AI 呼叫取消，回來的結果丟掉。
  - 目前的結果：正在念就停止（`readAll` 重設）；在等釐清或刪除確認就取消任務、還原資料；在等要全部念完嗎就結束等待；在錯誤確認就關閉彈窗（等於略過）。
  - 已經執行完的結果不還原；要退回用復原。
  - 回話顯示「已全部取消」，不念。

### 觸控

觸控馬上生效，不進入佇列；只影響已經執行的狀態，後面的結果輪到時用觸控之後的資料與黑板執行。

觸控的清單與能點的時機只寫在這張表；畫面上的位置與外觀見 [ui](ui.md)，各觸控做什麼見各功能的 spec。

| 觸控 | 什麼時候能點 | 對目前的結果 |
|---|---|---|
| 上一頁、下一頁、內容（複製文字） | 一直可以（上一頁、下一頁要有可以去的頁） | 不中斷 |
| 方框、「顯示已完成」開關（checkbox） | 目前的結果不在執行中、沒在等回答，也不在錯誤確認；而且有存檔、沒在背景讀取存檔（見 [storage](storage.md) 的「外部變動」「權限」） | 不中斷 |
| 復原、重做 | 同上，而且有可以回到的狀態 | 中斷報告，執行復原或重做；回報的文字也有報告顯示時間（用語音報告關閉的公式），之後換到下一個結果 |
| 關閉語音報告 | 一直可以 | 停止念；在等要全部念完嗎就結束等待；目前的結果改用語音報告關閉的公式，從關閉的那一刻計算 |
| 語音輸入開關 | 一直可以 | 不中斷；關閉只是停止聆聽，佇列照常進行 |
| 重試、略過（彈窗） | 輪到失敗的結果時 | 見 [recovery](recovery.md) |
| 提示對話框的箭頭與連結、工具列的提示按鈕 | 還沒凍結的提示對話框一直可以（原地換頁），凍結的不能點；開新的提示對話框要等目前的結果執行完、解讀好（見 [help](help.md) 的「說明」） | 不中斷；念提示時換頁會停掉那一頁 |
| 對話流的新訊息橫條、打開設定的齒輪 | 一直可以 | 不中斷 |

- 「處理中」指目前的結果正在執行；背景在解讀不算處理中。
- 說「復原」是照順序的使用者意圖，輪到時復原它前面最後一個結果；按復原是馬上復原目前最後執行的結果。

### 對話流

- 定稿的當下，這句話就以還沒送出的泡泡出現在對話流最下面（輸入的回饋，不是結果）：目前的結果之後、還沒呈現的使用者意圖（輸入、執行、結果佇列裡的），見 [ui](ui.md) 的「對話流」。
- 輪到處理時，變成對話流裡一般的泡泡。

### 紀錄

每句話從定稿起有一個編號；背景平行時各句的紀錄會交錯，每行照舊以 `[#編號 階段]` 開頭。新增的階段：

- **排隊**：進入輸入佇列
- **準備好**：產生使用者意圖；從開始解讀到準備好的耗時（規則判斷、校正、判斷都算）與內容摘要，例如 `耗時 9.8 sec：新增待辦（明天・看牙醫）`
- **輪到**：開始呈現
- **顯示時間**：報告顯示時間的秒數與算法（念完，或公式）
- **插隊**：這句話是回答，回答的是什麼問題
- **回音**：丟掉的句子與正在念的文字
- **全部取消**：清掉的句子編號

除錯 UI 的「目前的資訊」新增佇列狀態，每句一行，例如 `#3 目前（等回答）`、`#4 準備好`、`#5 判斷中`、`#6 排隊`。

### 結構

- **`IntentQueue`**（Domain，純邏輯）：三個佇列的狀態，包括順序、同時處理的上限、哪一個輪到、哪一句是回答（用開口時間）、全部取消。沒有 async，單元測試直接給事件。
- **`IntentPreparer`**（Application）：背景的部分，輸入一句話、畫面資訊與 AI，輸出使用者意圖。它拿不到待辦與黑板，由型別保證背景不改狀態。
- **小精靈**（`Elf`）：呈現的部分：輪到時執行器、顯示、報告、等回答、錯誤確認。
- 純函式：報告顯示時間、回音比對、全部取消的關鍵字。
- 報告顯示時間的等待用可替換的 sleep，單元測試不用真的等。

## Testing Decisions

- 單元測試（macOS，假的自動 AI、假的 TTS）：
  - 順序：B 比 A 先解讀好，仍然先呈現 A；同時最多 2 句，一句準備好下一句才開始
  - 背景不改狀態：A 在等刪除確認時，B 已經準備好，資料、黑板、undo 都不變，也沒有顯示或念
  - 等回答：後面的結果不出現；回答插隊；問題出現前開口、出現後才定稿的話不是回答；輔助關鍵字不算回答
  - 四種等待的回答（含 other、聽不懂、其他的話）都依上表處理
  - 錯誤確認只在輪到失敗的結果時出現；後面的使用者意圖照樣準備
  - 聊天：黑板或待辦沒變時用準備好的回應；變了就重做；只有時間或回話變時不重做
  - 報告顯示時間：念完就換；語音報告關閉與沒有要念的內容時用公式（上限 5 秒）；等回答時不計時
  - 全部取消：清空三個佇列、取消背景的 AI 呼叫；目前的結果依狀態結束；已經執行的結果不還原；校正改出的「全部取消」不觸發
  - 回音：念的期間開口、是念的文字的一部分就丟掉；不是一部分、或念完才開口就照常處理；念提示頁時說連結名稱、「下個提示」不丟掉
  - 說明的結果顯示就結束，後面的結果馬上輪到並中斷念提示
  - 觸控：按復原中斷報告並換到下一個；點方框不中斷；關閉語音報告後改用公式
  - 手動 AI 一次只解讀一句
- 手動驗證（實機）：
  - [ ] 連說三句，結果照順序出現，念完一個馬上接下一個
  - [ ] 回音消除漏掉時，小精靈自己的聲音不會變成新的指令
  - [ ] 語音報告關閉時，報告顯示時間夠看完
  - [ ] 「停止」從開口到停下的延遲可以接受

## Out of Scope

- 在暫定結果裡比對「停止」（暫定結果會變動，容易誤判；實測太慢時再考慮）
- 背景直接執行器
- AI 校正改出的「全部取消」
