# 備份

> **暫停**：待辦改存在提醒事項之後（見 [storage](storage.md)），換成備份會刪掉並重建使用者所有的提醒事項，遺失備註與清單。建立備份與換成備份的程式先註解掉，AI 判斷與規則判斷沒有這兩種指令，聊天的使用說明也不提。以下是暫停前的行為，恢復時從這裡改起。

## Problem Statement

待辦只存在這個 App 的存檔裡：重新開始、換裝置，或改用另一個功能相同的 App 時，資料帶不走。

## Solution

說「建立備份」，小精靈把所有待辦做成一份 JSON 文字放到剪貼簿；在另一個 App（或同一個 App）說「換成備份」，小精靈讀剪貼簿，用備份整份取代目前的待辦。功能相同的 App 共用同一個格式，可以互相換成對方的備份。

一句話：**備份是剪貼簿裡的一份 JSON；換成備份是整份取代，可以復原。**

## User Stories

1. 作為使用者，我想說一句話就把所有待辦複製出來，貼到哪裡保存都可以。
2. 作為使用者，我想在另一個功能相同的 App 說一句話，就換成這邊的待辦。
3. 作為使用者，我想換錯了可以一次復原。
4. 作為使用者，我想剪貼簿裡不是備份時，小精靈告訴我，而且不動我的待辦。
5. 作為開發者，我想在重新開始之前建立備份，測完再換回來。

## Implementation Decisions

### 執行器

建立備份、換成備份是執行器（見 [todos](todos.md)），AI 聽得懂其他說法（「把待辦存一份到剪貼簿」）；固定的說法由規則判斷產生，不送 AI（見 [judge-tool](judge-tool.md)）。

沒有觸控：備份只用說的（低觸控）。

### 格式

```json
{
  "format": "voicetodo-backup",
  "version": 1,
  "todos": [
    { "date": "2026-10-05", "time": "09:00", "content": "看牙醫", "isDone": false },
    { "date": "2026-10-06", "content": "買牙膏", "isDone": true, "reminderID": "x-apple-reminder://…" }
  ]
}
```

- 每筆待辦：`date`（`yyyy-MM-dd`）、`time`（`HH:mm`，沒有時間就省略，見 [todos](todos.md) 的「沒有時間的待辦」）、`content`、`isDone`、`reminderID`（從提醒事項匯入的才有；匯入已移除）。
- 不放 id 與「是否為示範資料」：id 是 App 內部的；換成備份後都是一般待辦。
- 讀的時候不認得的欄位忽略，讓另一個 App 多放的欄位不影響。

### 建立備份

- 目前所有的待辦（不只黑板上的）照格式做成 JSON，放到剪貼簿；不改變待辦、不移動黑板、不記 undo。
- 回報：「已建立備份，共 12 筆待辦，已放到剪貼簿」，並念出來。

### 換成備份

- 讀剪貼簿的文字，整份檢查：`format` 是 `voicetodo-backup`、`version` 是 1、每筆的日期與時間合法、內容不是空白。有一項不對就整份不用，待辦不變，回報原因（不念，和放棄相同）：
  - 剪貼簿沒有文字或不是 JSON、`format` 不對：「剪貼簿裡沒有備份」
  - `version` 不是 1：「看不懂第 2 版的備份」
  - 某一筆不合法：「備份的第 3 筆不合法：日期 2026-13-01」
- 合法時用備份取代所有的待辦（沒有待辦的備份會清空待辦），重新編 id，存檔；記成 undo 的一個狀態，一次復原就回到換之前。
- 黑板換成「所有」，讓換進來的待辦看得到；查詢條件清除，checkbox 不變（和「顯示全部」相同）。
- 回報：「已換成備份，共 12 筆待辦」，並念出來。
- 不另外確認：換錯可以一次復原。
- iOS 讀別的 App 放進剪貼簿的內容時，系統會跳出「允許貼上」；按的是系統的對話框，不違反低觸控（和提醒事項的權限相同）。

### 結構

- 格式的編碼與檢查是純邏輯，放在 Domain（`Backup`）。
- 剪貼簿是一個介面（放入文字、讀出文字），系統剪貼簿是它的實作；測試用假的剪貼簿。

## Testing Decisions

- 格式（純邏輯）：
  - 建立後再讀回，內容相同；沒有時間、沒有 `reminderID` 時不輸出這兩個欄位；不輸出 id 與示範資料
  - 不認得的欄位忽略
  - 不是 JSON、`format` 不對、`version` 不是 1、日期不合法、時間不合法、內容空白：整份不用，回報對應的原因
- 規則判斷：建立備份、換成備份各自的說法；標點與空白不影響
- 小精靈（假的剪貼簿）：
  - 建立備份：剪貼簿是所有待辦的備份，待辦不變；固定的說法不送 AI，AI 回傳建立備份時結果相同
  - 換成備份：待辦換成備份，示範資料標記清除，黑板是「所有」；undo 一次回到換之前
  - 剪貼簿不是備份：待辦不變，回報原因
- 手動驗證（實機）：
  - [ ] macOS 建立備份後貼到文字編輯器，是格式化的 JSON
  - [ ] iOS 說「換成備份」時跳出「允許貼上」，允許後換成備份
  - [ ] 在另一個 App 建立的備份，這裡可以換成；反過來也可以

## Out of Scope

- 用 URL scheme 或 Universal Link 直接開啟另一個 App 傳資料：剪貼簿已經涵蓋同一台裝置、跨裝置與手動保存；需要時再加，格式不變。Universal Link 在對方沒裝 App 時會用 Safari 開，網址裡的待辦會送到網站上，不採用。
- 合併：備份只能整份取代
- 分享檔案（AirDrop、檔案 App）
- 備份設定（AI、API key、checkbox）與測試紀錄
- 自動、定期備份
