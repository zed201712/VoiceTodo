# 判斷階段

## Problem Statement

使用者用一句話說出需求，可能包含多件事、可能沒講清楚。要推斷意圖，只透過執行器執行；資訊不足時問清楚，不直接猜。

## Solution

AI 只做一次判斷：把一句話翻成指令清單。指令依序執行成任務：執行器換算日期、找出目標，需要時提出釐清與刪除確認。

判斷的結果一律是 JSON 字串：自動 AI 的結構化輸出轉成 JSON，手動 AI 直接給 JSON，兩者走同一個解析器。切換成手動 AI 時，App 顯示使用者提示詞，等開發者貼回 AI 回應。

一句話：**AI 把話翻成 JSON 指令清單，一次執行一條；不清楚就釐清，失敗或取消就還原這條指令。**

## User Stories

1. 作為使用者，我想說「明天要看牙醫」，小精靈就在明天新增待辦。
2. 作為使用者，我想一句話說兩件事（「新增明天買水果，刪除下次的買牛奶」），小精靈依序處理。
3. 作為使用者，我想說「刪除買牛奶」，小精靈在我看到的待辦裡找出是哪一筆，不用我說日期。
4. 作為使用者，我想問「下週有什麼事？」，小精靈直接把結果顯示出來。
5. 作為使用者，我想找到多筆或沒講清楚時小精靈問我，而不是亂猜。
6. 作為使用者，我想回答小精靈的問題時，可以直接補充（「10 月 9 號那個」），不用照固定格式。
7. 作為使用者，我想刪除前小精靈列出範圍和項目，我說「好」才刪。
8. 作為使用者，我想說「算了」就取消，資料回到這條指令開始前。
9. 作為使用者，我想找不到目標或執行失敗時小精靈不要改猜別的，而是放棄並還原。
10. 作為使用者，我想小精靈處理中說的話依序處理，不被丟掉；結果照我說的順序出現。
11. 作為使用者，我想小精靈顯示接下來要做的指令與正在執行的指令。
12. 作為開發者，我想在除錯 UI 看到 AI 輸出的指令清單與每條指令的執行結果，在 console 看到完整的判斷資訊。
13. 作為開發者，我想切換成手動 AI，把同樣的請求交給 App 外的任意 AI，比較不同 AI 的判斷成效。

## Implementation Decisions

### 流程

整體的路徑（關鍵字、校正、任務流程與聊天的分支）見 [flow](flow.md)；以下是判斷這一段。

1. 一般判斷在背景進行：從輸入佇列照順序取出一句話，解讀成使用者意圖，輪到時才執行指令（見 [queue](queue.md)）；釐清中、刪除確認中的回答插隊，馬上判斷。要送去判斷時，校正錯別字和用原句的判斷同時開始，校正採用了新句子就改用新句子重判（見 [correction](correction.md) 的「和判斷同時進行」）。
2. **等待刪除確認中**：這句話先判斷 yes／no／other（見「刪除確認」）；other 時改做釐清後判斷。
3. **釐清中**（找到多筆、資訊不足）：這句話連同釐清問題與原本的指令一起送 AI（釐清後判斷），輸出新的指令清單。原本的指令取消，改執行新的指令；同一句話裡還沒執行的指令排在後面照常執行。
   - 釐清中、一般判斷之前都先用規則判斷：整句符合固定句型就直接產生指令，不送 AI（見 [judge-tool](judge-tool.md)）。
4. **其他**：AI 把這句話翻成指令清單（一般判斷，一次呼叫）。清單裡有「聽不懂」或清單為空時，整句一條都不執行，交給聊天階段回話（見 [chat](chat.md)）；釐清後判斷時和空清單相同，原本的任務取消，不聊天：進入釐清代表使用者已經下了正確的任務。
   - 問 App 怎麼用（有什麼功能、要怎麼說、要範例、例子或說明）：對得到某一頁提示就輸出說明（那一頁，見 [help](help.md)）；對不到才輸出「聽不懂」，由聊天回答（見 [chat](chat.md) 的「前提」）。優先順序：主功能的指令 ＞ 說明。
   - 「聽不懂」是明確的選項：只能輸出空清單時，模型傾向輸出不用填欄位的指令（當時是清除、建立示範資料），雜音因此改到資料。和其他指令混在一起代表模型也不確定，所以整句都不執行。空清單照樣接受（手動 AI）。
5. 依序執行指令，一次一條。每條指令就是一個任務。
6. 輪到的使用者意圖處理完（所有指令結束，或停在釐清、刪除確認）時，念出成功的結果與問題（見 [spoken-report](spoken-report.md)）；報告顯示時間結束、沒在等回答，才換到下一個（見 [queue](queue.md)）。

### 判斷的來源

AI 的請求有三種，自動 AI 與手動 AI 收到的請求文字完全相同：

| 請求 | 請求文字 | 回應 |
|---|---|---|
| 一般判斷 | 這句話；最底下的提示對話框還沒凍結時，是 `提示：<頁名>（連結：<連結名稱>）`、`使用者說：<這句話>`，各一行（見 [help](help.md) 的「判斷」） | 指令清單 JSON |
| 釐清後判斷 | `小精靈剛才問：<問題>`、`原本的指令：<摘要>`、`使用者說：<這句話>`，各一行 | 指令清單 JSON |
| 刪除確認 | `問題：<確認問題>`、`回答：<這句話>`，各一行 | `{"answer": "yes"}`、`{"answer": "no"}` 或 `{"answer": "other"}` |

- **自動 AI**：App 送出請求、取得 JSON 字串後交給解析器（見「自動 AI」）。
- **手動 AI**：除錯 UI 的自動 AI 開關關閉時，每次請求都顯示在除錯 UI（種類與請求文字），App 等開發者貼回 AI 回應，不設時限。手動 AI 的提示詞見 [judge-prompt](../eval/judge-prompt.md)；改指令定義或請求格式時要同步更新。
- 開關只影響下一次請求：已經在等 AI 回應時切換，這筆仍然等 AI 回應。
- App 沒有在等 AI 回應時貼上的 JSON 不處理，回話回報「目前沒有等待手動 AI」。

### JSON 格式

指令清單：

```json
{"commands": [
  {"action": "新增待辦", "date": "明天下午3點", "content": "買水果"},
  {"action": "修改待辦", "keyword": "部門會議", "newDate": "下週週一", "newContent": "部門週會"}
]}
```

- `action` 是 [todos](todos.md) 的指令名稱；其他欄位：`keyword`、`content`、`newContent`、`number`、`page`（字串），`isDone`、`showDone`（布林），`date`、`newDate`（日期字串）。刪除待辦的 `isDone: true` 是只刪已完成的。`showDone` 是設定顯示的「完成」是否勾選。`number` 是黑板上的編號，一個（`"2"`）或一段（`"3~10"`），見 [todos](todos.md) 的「編號」；有 `number` 時不用 `date`、`keyword`。`page` 是說明的頁名，只能是 [help](help.md) 的「提示頁」裡的頁名。
- 日期字串的語法見 [date-time](date-time.md)。解析不了時，執行時放棄並回報解析結果。
- 空字串視為沒給；不認得的欄位忽略。
- 指令名稱與日期說法只認繁體中文（提示詞要求 AI 輸出繁體）。解析前先把回應的簡體字轉成繁體（ICU 的 `Hans-Hant`）：自動 AI 偶爾輸出簡體，轉換是固定的規則，由 App 處理。「周」本身也是繁體，不會轉成「週」。
- date、newDate 解析後套用說法改寫（見 [judge-tool](judge-tool.md) 的「說法改寫」）：「號」→「日」、「兩點」→「2點」、「下週一」→「下週週一」等。這些是提示詞已經要求的寫法，AI（尤其是 Foundation Models）常沒照寫，固定的規則由 App 處理；AI 能用的說法清單不變。
- 另外兩項固定的修補，同樣是提示詞已經要求、AI（尤其是 Foundation Models）常沒照做的：
  - keyword 整個是編號（「第一項」「第3到5項」，同 [judge-tool](judge-tool.md) 的 `<編號>`）時，改成 number。
  - 新增待辦的 content 開頭是時刻（可以有時段，一定要有「點」，例如「下午3點半看牙醫」），而且 date 沒有時間時，把時刻移到 date 的最後。沒有「點」的不移（「下午茶」）。
- **不合法**（不是 JSON、沒有 `commands`、`action` 不認得、欄位型別錯誤，例如日期給字串）：和自動 AI 判斷失敗相同，進入錯誤確認。
- 刪除確認的回應不合法時當成 no。

### 指令

AI 只能輸出 [todos](todos.md) 定義的指令。目標待辦用「日期＋內容關鍵字」描述，不用 id；日期由 AI 從公開的說法中組成，執行器換算（見 [date-time](date-time.md)）。AI 只照使用者的話填欄位，不推測日期；沒說日期時以黑板為準，由執行器處理（見 [todos](todos.md) 的「沒說日期時：以黑板為準」）。

### 找出目標

- 找目標的指令只在黑板上看得到的待辦裡找（見 [todos](todos.md) 的「黑板」）；沒給日期時在整個黑板上找。
- **日期**換算成日期範圍：單日（今天、下週＋週五、10月3日）、整週（下週）、整月（下個月）、整年（明年）、「目前」；「下次」＝今天起最早符合的一筆那一天。黑板沒有涵蓋這個範圍時先移動黑板（見 [todos](todos.md) 的「黑板」的「範圍」）；只找這個範圍內的待辦。沒給日期時黑板不動。
- **時間**換算成範圍（「晚上」是 18:00 以後，見 [date-time](date-time.md) 的「時間」），只找時間在範圍內的待辦，沒有時間的不列入；沒給時間不篩選時間。
- **內容內容關鍵字**：待辦內容包含內容關鍵字即符合；沒給內容關鍵字時全部符合（「刪除全部」是黑板上的全部）。
- **編號**：黑板上的那幾筆，不看日期與內容關鍵字（見 [todos](todos.md) 的「編號」）；每一筆都執行，不釐清（刪除例外，見「刪除確認」）。
- 找目標的指令沒有編號時（刪除例外，見「刪除確認」）：符合 1 筆就執行；多筆就釐清（列出各筆日期與內容，問是哪一筆）；0 筆就放棄，回話只說「找不到」。
- 新增沒給日期而黑板超過一天（「目前」除外，用今天）時，釐清「你是指 10/5–10/11 的哪一天？」（見 [todos](todos.md) 的「沒說日期時：以黑板為準」）。
- 刪除：符合的全部列入確認問題；0 筆就放棄，回話只說「找不到」。

### 任務結束方式

| 結束方式 | 條件 | 資料 |
|---|---|---|
| 完成 | 指令執行了，或問句回答了 | 保留 |
| 釐清 | 找到多筆、資訊不足、刪除確認 | 任務暫停，等下一句話 |
| 取消 | 使用者表示不要，或刪除確認回答不是 yes | 還原到任務開始前 |
| 放棄 | 找不到目標、參數不合法 | 還原到任務開始前 |

- 任務開始前對資料（待辦）拍快照，取消或放棄時整個還原。釐清期間快照保留到任務結束。
- 一般判斷或釐清後判斷時自動 AI 失敗、AI 回應不合法：輪到時進入錯誤確認，後面的結果不出現，回話回報原因（例如「判斷失敗：內容太長」），等使用者重試或略過（見 [recovery](recovery.md)）。失敗原因由自動 AI 的實作提供。
- 釐清時沒有時限。

### 刪除確認

1. 刪除指令找到目標後，任務記住刪除指令與要刪的待辦，回話顯示「即將刪除<範圍>（N 項）：<各項日期與內容>。要刪掉嗎？」；2 項以上時結尾是「這 N 項都要刪掉嗎？」。日期與內容關鍵字都沒給時，<範圍>是「所有待辦」。說法不含回答的關鍵字（見 [spoken-report](spoken-report.md) 的「念問題」）。
2. 下一句話先用關鍵字判斷：去掉標點與空白後**完全等於**下列任一詞（英文不分大小寫）。
   - yes：好、好的、好啊、可以、確定、確認、是、對、沒問題、全部、同意、ok、yes
   - no：不、不要、不用、取消、算了、否、no
3. 比對不到時先用規則判斷：整句符合固定句型就是新需求，原本的刪除取消、執行新指令（見 [judge-tool](judge-tool.md)）；也沒命中才交給 AI（刪除確認請求），判斷三種之一：
   - yes：同意刪除列出的全部；回答要刪的是列出的全部（例如「全部刪掉」「兩個都刪」）也算。
   - other：只指定其中某些項目（「刪除買牛奶」「只刪第二個」），或說了新需求。
   - no：其他情況，包括拒絕、猶豫或不明確。AI 失敗或回應不合法時也當成 no。
4. yes：刪除記住的待辦，任務完成。no：任務取消。
   other：任務取消（還原、不回報「已取消刪除」），這句話改做釐清後判斷（確認問題、原本的刪除指令與這句話），照輸出的指令繼續，和「流程」第 3 點相同。指定其中一項時，AI 輸出範圍縮小的刪除指令，再進入一次刪除確認；刪除一定要經過確認。
5. 用完全相等而非包含：「不好」包含「好」，用包含會誤判成 yes。

### 自動 AI

App 透過同一個介面使用自動 AI：判斷（一般判斷、釐清後判斷）與刪除確認各一個方法，收到請求文字、回傳 JSON 字串。用哪個實作由設定決定（見 [settings](settings.md)），可以在執行中更換，換模型不用改流程；沒有可以使用的 AI 時，判斷失敗並進入錯誤確認。手動 AI 不走這個介面：它要等開發者貼回。

- 每個實作自己處理模型的細節：提示詞、輸出結構、錯誤（失敗時丟出可以直接顯示的原因）與 console 的詳細紀錄。
- **Foundation Models**：結構化輸出（`@Generable`）。不能同時成立的選項用 enum 表示，結構上只允許合法的輸出：指令是一個 enum，日期是字串，寫法由提示詞說明。欄位依宣告的順序產生，要找待辦的指令先產生內容關鍵字再產生日期。裝置端模型讀提示詞很慢，所以用 FM 專用的精簡提示詞（比共用的短；FM 不校正，提示詞也不提錯字（實測加了反而變差）；例外地放句型參考，因為小模型只看說明常選錯指令；用 < > 的句型，具體的例句會被照抄）；輸出結構不放進提示詞（放進去每句多約 2,500 token，實測反而更常選錯），結構仍然限制輸出；指令最多 3 條；和判斷同時問一個是非題（是不是要 App 做事），否就是聽不懂（小模型對無關的話也會編出指令；釐清後判斷不問）；先 prewarm 好下一次判斷的 session。每次請求一個新的 session，不保留紀錄；超出上下文長度時原因是「內容太長」。
- **Ollama**：Ollama 的 `/api/chat`，位址（IP、port）由設定決定，以 JSON Schema（`format`）限制輸出結構，提示詞與手動 AI 的共用核心相同（見 [judge-prompt](../eval/judge-prompt.md)）。每次請求只帶提示詞與這個請求，不保留紀錄；temperature 0、不開 thinking。輸出上限：判斷 512 token、刪除確認 20 token，超過時原因是「輸出超過上限」；沒啟動、找不到模型、逾時（120 秒）時回報對應的原因。
- **Gemini**：Gemini API 的 `generateContent`，以 JSON Schema（`responseJsonSchema`）要求輸出結構，提示詞與 Schema 和 Ollama 相同；Gemini 照 Schema 的欄位順序產生輸出，順序會影響判斷，所以每個物件加上固定的 `propertyOrdering`。API key 讀設定（Keychain），沒有時狀態與失敗原因是「未設定 Gemini API key，請到設定填入」。每次請求只帶提示詞與這個請求，不保留紀錄；temperature 0、不送 thinking 參數。輸出上限：判斷 512 token、刪除確認 64 token（隱藏的思考也算在內），超過時原因是「輸出超過上限」；服務忙線時原因是「Gemini 忙線，請再說一次」，其他 API 錯誤（key 無效、超過配額、找不到模型）回報 API 的訊息；沒有網路、逾時（60 秒）時回報對應的原因。不重試。
- instructions 包含指令的定義（種類、欄位與說明）；不放具體例句：模型會把例句當答案照抄。

### 紀錄

每句話從定稿起有一個編號；console 與測試紀錄的每一行以 `[#編號 階段]` 開頭，一句話的經過是連續可追的一段：

- **輸入**：來源（語音／文字）與內容
- **判斷**：來源（自動 AI／手動 AI）與請求種類、自動 AI 用的固定提示詞名稱、請求文字、回應 JSON（自動 AI 附耗時）、失敗原因
- **指令 i/n**：指令摘要、結束方式與回報
- **還原**：取消或放棄時還原資料
- **確認**：刪除確認的判斷方式（關鍵字／AI）、yes／no／other 與結果
- **小精靈**：這句話處理完時的回話內容
- **對話流**：話與回話加入對話流、校正後的句子取代原句、回話內容改變（被蓋掉的回話沒有留在對話流時註明「舊的沒留下」），見 [ui](ui.md) 的「對話流」
- **黑板**：黑板看得到的內容（標題或待辦）一變就印出整個黑板，記在引起變動的那句話底下；內容和畫面資訊的黑板相同（標題一行，接著每筆帶編號，見 [screen-info](screen-info.md)），但不截斷。內容沒變就不印

**固定提示詞**：自動 AI 每次請求都帶同一份提示詞與輸出結構，不隨句子改變。自動 AI 提供兩份：「判斷提示詞」（一般判斷、釐清後判斷）與「刪除確認提示詞」（有校正、聊天功能的另有「校正提示詞」「聊天提示詞」，見 [correction](correction.md)、[chat](chat.md)），各自是送出的提示詞與輸出結構（Ollama、Gemini 是送出的 JSON Schema，Foundation Models 是 `@Generable` 產生的 schema）。設定的「預設提示詞」打開時（見 [settings](settings.md) 的「開發」），複製的測試紀錄開頭完整列出每一份的定義，讓複製的紀錄自己就完整重現 AI 收到的內容；關的時候不列，紀錄比較短。每筆自動 AI 的請求只寫名稱（例如「自動 AI｜一般判斷｜判斷提示詞」）。

自動 AI 的其他詳細資訊只印到 console，由實作決定內容（Foundation Models：完整 transcript、耗時與 token 用量；Ollama、Gemini：提示詞、請求、回應、耗時與 token 用量）。

### 回報

- AI 輸出指令後，回話顯示接下來要做的指令；執行時顯示正在執行的指令；結束時顯示任務產生的結果（例如「已新增 ☐ 9/30（三） 買水果」、查詢到的件數、釐清或確認問題、取消或放棄的原因）。查詢的待辦顯示在黑板上，回話不再列出。
- 不用 AI 寫的文字（聊天的回應例外，見 [chat](chat.md)）。

## Testing Decisions

- 以單元測試鎖住，不依賴 Foundation Models：直接給指令清單，或切換成手動 AI、以 AI 回應驅動 App。
  - JSON：每種指令轉成 JSON 再解析回來不變；不合法的 JSON、不認得的 action、型別錯誤都失敗；空字串視為沒給
  - 輸出結構：每種指令的欄位與必填只定義一次，Ollama、Gemini 的 JSON Schema 由它產生；Foundation Models 的結構和它一致；手動 AI 的提示詞和判斷提示詞一致
  - 自動 AI：以假的實作驅動 App，判斷後依序執行；失敗時取消這句話，回報實作提供的原因
  - 手動 AI：多行測試輸入各自是一句話，一次只解讀一句，前一句的回應貼回後才出現下一句的請求；沒在等時貼的 JSON 不處理
  - 找出目標：日期換算、內容關鍵字比對、「下次」取最早一筆、多筆釐清、0 筆放棄；只找黑板上看得到的
  - 刪除確認：關鍵字 yes／no、完全相等（「不好」不算 yes）、比對不到交給 AI；other 時取消原本的刪除，改做釐清後判斷，縮小範圍後再確認一次
  - 失敗與取消時還原；前一條指令的結果保留
  - 「聽不懂」單獨或混在其他指令裡：都不執行、不改資料
  - 結果照輸入佇列的順序呈現（見 [queue](queue.md) 的測試）
- 手動驗證：
  - [ ] 一句話兩件事輸出兩條指令
  - [ ] 「刪除下次的買牛奶」黑板移到那一天，找到那筆並確認
  - [ ] 找到多筆時釐清，回答後執行
  - [ ] 每句話只呼叫一次 AI，耗時
  - [ ] 用 [judge-cases](../eval/judge-cases.md) 比較自動 AI 與手動 AI

## Out of Scope

- 同時執行多個任務（背景只解讀，任務照順序執行，見 [queue](queue.md)）
- 依查詢結果做後續決定（例如「把最早的那個會議改到下週」以外的比較）
- 釐清的時限
