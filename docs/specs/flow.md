# 流程

## Problem Statement

一句話從定稿到結束，會經過關鍵字、校正、判斷、任務、釐清、聊天等步驟，這些規則原本散在各份 spec。哪些話走哪一條路、在哪裡結束，需要有一個地方從頭講完。

## Solution

AI 判斷決定一句話走哪一條路：**任務流程**（包含釐清 loop），或**聊天階段**。進入釐清代表使用者已經下了正確的任務，所以釐清中聽不懂就取消，不聊天；聊天只會從一般判斷進入。

一句話：**App 先處理關鍵字；其餘的話在背景校正後交給 AI 判斷，它決定是執行任務，還是聊天；結果照說話的順序呈現。**

## User Stories

1. 作為使用者，我想說了 App 做不到的事或無意義的話時，小精靈自然地回一句，而不是只說「聽不懂」。
2. 作為使用者，我想小精靈在問我問題時，我答非所問就取消那件事，不要跟我聊起來。
3. 作為開發者，我想從一份 spec 知道一句話會走哪一條路、在哪裡結束。

## Implementation Decisions

### 一句話的路徑

一句話在背景解讀成使用者意圖，再照說話的順序輪流執行、呈現（佇列、報告顯示時間與插隊見 [queue](queue.md)）。

```
定稿（語音或測試輸入的一行）
│
├─ 優先關鍵字「全部取消」（只比對原句）→ 清空三個佇列，結束目前的結果
├─ 輔助關鍵字 → 馬上處理，不碰任務與佇列
├─ 回音（念的期間開口、是正在念的文字的一部分）→ 丟掉
├─ 目前的結果在等回答 → 這句話是回答，插隊（見下方「回答」）
└─ 其他 → 輸入佇列，開始一個生命週期

背景（執行佇列，同時最多 2 句）：解讀成使用者意圖，不改任何狀態
│  （定稿時已經由規則校正拿掉多餘的空白，並拍下畫面資訊的快照，見 [correction](correction.md) 的「規則校正」）
├─ 規則判斷命中 → 使用者意圖：指令清單
└─ 校正 ∥ 一般判斷（平行處理階段）
     ├─ 有指令 → 使用者意圖：指令清單
     ├─ 聽不懂／空清單 → 聊天 → 使用者意圖：聊天的回應
     └─ 判斷失敗 → 使用者意圖：判斷失敗
│
→ 結果佇列（照輸入順序）

輪到一個使用者意圖（目前的結果）
├─ 指令清單 → 任務流程：依序執行，遇到釐清或刪除確認就停下，等回答
├─ 聊天的回應 → 黑板或待辦和快照時不同就重做聊天，再顯示
└─ 判斷失敗 → 錯誤確認，等回答
│
→ 顯示、語音報告念出成功的結果與聊天的回應；查詢超過 3 項時可能問要不要全部念完
→ 報告顯示時間結束、沒在等回答 → 下一個

回答（插隊，屬於目前的生命週期）
├─ 刪除確認：關鍵字判斷 yes／no → 規則判斷（命中就是新需求）→ 比對不到交給 AI；other 時改做釐清後判斷
├─ 釐清：規則判斷（命中就是新需求）→ 校正 ∥ 釐清後判斷
│    ├─ 有指令 → 原本的任務取消，執行新的指令（可能再進入釐清）
│    └─ 聽不懂／空清單 → 原本的任務取消，結束（不聊天）
├─ 要全部念完嗎：要／不要；其他的話照常判斷，馬上呈現
└─ 錯誤確認：重試、略過、復原、重做；其他的話等於略過，照常判斷，馬上呈現
```

- **使用者意圖產生的時機**：平行處理階段結束時；規則判斷命中時，比對到的當下。需要釐清的使用者意圖，也是一個（待釐清的）使用者意圖，回答修改它，不產生新的。
- 規則判斷：每次呼叫 AI 判斷或 AI 刪除確認之前調用，命中就取代那一次的 AI 判斷；在釐清、刪除確認中命中時，原本的任務取消、執行新指令（見 [judge-tool](judge-tool.md)）。
- `校正 ∥ 判斷`：平行處理階段，兩者同時開始，各執行一次；兩邊都回來、決定採用哪一份判斷後才結束。校正採用了新句子就作廢原句的判斷、用新句子重判（見 [correction](correction.md) 的「和判斷同時進行」）。
- 作廢後的重判與聊天，都在平行處理階段結束之後才開始；聊天只看採用的判斷。
- 畫面資訊的快照在定稿時拍（見 [screen-info](screen-info.md)），這句話的校正與聊天都用它；回答用回答定稿時的快照。
- 判斷失敗（自動 AI 失敗、AI 回應不合法）時，輪到它才進入錯誤確認，等重試或略過（見 [recovery](recovery.md)）。聊天失敗不進入，退回「聽不懂」（見 [chat](chat.md)）。

### App 直接處理的話

去掉標點與空白後完全等於關鍵字時，不送 AI：

| 類別 | 時機 | 關鍵字 | 見 |
|---|---|---|---|
| 優先 | 定稿當下，只比對原句；影響任務與佇列 | 全部取消、全部停止、取消全部、停止全部 | [queue](queue.md) |
| 輔助 | 定稿當下，任何狀態；只控制報告與麥克風，不碰任務與佇列 | 關閉語音、停止、打開／關閉語音報告、打開／關閉音效 | [ui](ui.md)、[spoken-report](spoken-report.md) |
| 回答 | 目前的結果在等回答時，插隊 | 刪除確認的 yes／no；要全部念完嗎的要／不要；錯誤確認的重試、略過、復原、重做 | [judgment](judgment.md)、[spoken-report](spoken-report.md)、[recovery](recovery.md) |

## Testing Decisions

各分支的單元測試寫在各段的 spec；這份 spec 本身新增的規則只有「釐清中聽不懂不聊天」，見 [chat](chat.md) 的測試；佇列的測試見 [queue](queue.md)。

## Out of Scope

- 同時執行多句話的任務（背景只解讀，見 [queue](queue.md)）
