# 畫面資訊

## Problem Statement

自動 AI 要理解使用者的話，常需要使用者當下看到的東西：黑板上的待辦名稱可以修正錯字，下一件待辦可以拿來接話。但畫面上的內容可能很長（黑板上幾十筆待辦、回話列出整串回報），全部送出會浪費 token。

## Solution

概念上，所有自動 AI 都看得到使用者當下看到的畫面。App 在一句話定稿時拍下畫面的快照，整理成幾個欄位，每個欄位最多 100 字。超過時由 App 依欄位自己的單位（一筆待辦、一行、一句）截斷，不直接取前 100 字。

一句話：**AI 看到的是使用者開口時看到的畫面，每個欄位最多 100 字，在單位的邊界截斷。**

目前用到畫面資訊的是校正（見 [correction](correction.md)）與聊天（見 [chat](chat.md)）。AI 判斷在概念上也看得到畫面，但**暫時只加還沒凍結的提示對話框**那一行（見 [help](help.md) 的「判斷」），其他欄位不加。這是技術上的理由：判斷是目前缺失最多的地方，請求多了內容會改變它的行為，要用 [judge-cases](../eval/judge-cases.md) 重新實測；而且手動 AI 的請求格式與 [judge-prompt](../eval/judge-prompt.md) 也要同步修改。

## User Stories

1. 作為使用者，我想小精靈理解我的話時，參考的是我眼前看到的東西。
2. 作為使用者，我想小精靈的回話可以提到我畫面上的待辦，例如下一件要做的事。
3. 作為開發者，我想送給 AI 的畫面資訊有固定的上限，token 用量可以預期。

## Implementation Decisions

### 欄位

| 欄位 | 內容 | 截斷單位 |
|---|---|---|
| 現在 | 現在的日期與時刻，例如 `2026/10/2（五）14:30` | 不截斷 |
| 黑板 | 第一行是標題（範圍與查詢條件，和畫面相同，例如 `下週 10/5–10/11 會議`；標題是空的就省略這一行），接著每筆看得到的待辦一行：編號（見 [todos](todos.md) 的「編號」）加上列出待辦的格式，例如 `3. ☐ 10/3（六） 06:00 看牙醫`；寫完整的日期、不分組（「明天」這類詞過了那天就不對）；沒有待辦時是「無資料」 | 一行 |
| 小精靈說 | 最後一則回話的內容（開場問候不算；提示對話框是目前那一頁）；去掉空行與分隔線 | 一行 |
| 小精靈剛才問 | 等釐清或刪除確認時，那個問題；沒有就省略整個欄位 | 一句 |
| 使用者說 | 這句話（校正前的原文；聊天時是採用的句子） | 一句 |

- 「現在」雖然不在 App 畫面裡，但裝置的狀態列看得到，所以算進畫面資訊。
- 不送：小精靈的插畫、對話流裡更早的話與回話、排隊中與正在說的話、按鈕、便條（它是給使用者的引導，見 [help](help.md) 的「便條」）。
- 「一句」以 `。！？` 與換行切開，標點留在前一句。

### 快照的時機

一句話定稿時拍快照：AI 看到的是使用者說這句話時看到的畫面。結果照順序呈現（見 [queue](queue.md)），輪到這句話時畫面可能已經被前面的結果改變，所以不在輪到時拍。

- 錯誤確認後重試時，沿用同一份快照。
- 聊天在背景先準備；輪到時黑板或待辦和快照不同，就拍新的快照重做聊天（見 [chat](chat.md)）。

### 截斷

每個欄位分別處理，100 字只算欄位的內容，不含欄位名稱與省略標記：

1. 從頭開始依序取完整的單位；加上下一個單位會超過 100 字時就停。
2. 有被省略的單位時，最後加一行標記：黑板是 `…還有 N 項`，其他欄位是 `…`。
3. 第一個單位本身就超過 100 字時，在前 100 字裡最後一個標點（`。！？；，、`）之後切開，再加 `…`；沒有標點時取前 100 字。

聊天的回應超過 100 字時，也用同樣的規則以「一句」截斷。

### 請求文字

欄位依上表的順序，每個欄位以 `欄位名稱：` 開頭；有多行的欄位，第一行接在名稱後面，其餘各占一行：

```
現在：2026/10/2（五）14:30
黑板：下週 10/5–10/11
1. ☐ 10/5（一） 09:00 看牙醫
2. ☐ 10/6（二） 15:00 部門會議
…還有 3 項
小精靈說：已新增 ☐ 10/3（六） 06:00 看牙醫
小精靈剛才問：要刪除哪一個？
使用者說：嗯
```

沒有內容的欄位（例如還沒有回話）整個省略。

### 結構

畫面資訊是 Application 層的純值型別（`ScreenInfo`）：欄位、截斷與請求文字都是純函式，不依賴 UI，單元測試直接給值。快照由小精靈在一句話定稿時產生。

## Testing Decisions

- 單元測試（macOS）：
  - 截斷：剛好 100 字不省略；超過時停在單位的邊界並加標記，黑板寫出省略的筆數；第一個單位太長時在最後一個標點後切開；沒有標點時取前 100 字
  - 請求文字：欄位順序；沒有內容的欄位省略；黑板沒有待辦是「無資料」；沒有釐清時沒有「小精靈剛才問」
  - 快照：在定稿時拍，拿到的是當時的回話與黑板，便條不在裡面；還沒凍結的提示那一頁與連結也在快照裡（給判斷用）；之後前面的結果改了畫面也不變；重試沿用同一份

## Out of Scope

- AI 判斷的畫面資訊，提示那一行以外（理由見上方）
- 依 token 數而非字數截斷
- 由 AI 摘要過長的欄位
